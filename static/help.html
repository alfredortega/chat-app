1. Getting Started & Setup

Before you can chat, the application needs to know which AI service to connect to and where to save any files it creates. This is a one-time setup. Follow the steps below in order.

Where to find these options: click the ⚙ Settings gear icon in the top-right corner of the application. All setup options live in this window.

Required settings

The application cannot answer messages until you have added at least one API Endpoint (see the API Endpoints section for full details).

1Add an API Endpoint

In Settings, click New Endpoint and provide a name, the API base URL of your provider (for example https://api.openai.com/v1), and the API key issued by that provider. Tick Use as the default endpoint so new conversations use it automatically. You can add as many endpoints as you like and switch between them per conversation.

2Default Model (per endpoint)

Every endpoint has its own default model. Once you enter a valid URL and key in the endpoint window, the Default Model list fills automatically with the models that endpoint offers — pick one. This model is used whenever you start a new conversation on that endpoint.

If you mark an endpoint as the default endpoint, it must have a default model chosen. The app will not let you save a default endpoint without one, and if you switch the default endpoint to one that has no default model yet, you will be prompted to pick one first.

4Default Output Folder recommended

When you ask the assistant to save or create a file, it writes it into this folder. Enter a full folder path, for example C:/Users/Me/Documents/output. If left blank, file-saving features may not work as expected, so setting it is strongly recommended.

5Folder Browser Starting Path optional

When you browse your computer for a folder, the browser opens at this location by default. Setting it to a folder you use often saves clicking. If left blank, browsing starts at your home directory.

When you have entered your details, click Save. The model list refreshes automatically, and you are ready to start chatting.

Setup at a glance: at a minimum you need one API Endpoint (name + URL + key) marked as default, and that endpoint needs a default model. Adding a Default Output Folder makes day-to-day use much smoother.

3. API Endpoints

An API Endpoint is a single AI provider you can connect to. Each endpoint stores its own name, API base URL, API key, and default model. You can add several endpoints (for example a hosted provider and a local server) and pick which one each conversation uses.

Adding and editing endpoints

Open Settings and look at the API Endpoints section at the top:

  • New Endpoint: click it, then fill in:
    • Name — a friendly label, e.g. "OpenAI" or "Local LMStudio".
    • API Base URL — the full base URL including the version path, e.g. https://api.openai.com/v1. It is used verbatim; nothing is appended.
    • API Key — the credential from your provider. Local servers (LMStudio, Ollama) usually don't need one, so you can leave it blank.
    • Default Model — once a valid URL and key are entered, the model list loads automatically; choose the model this endpoint should use by default for new conversations. (For a brand-new endpoint the list can only load after the endpoint is saved — save it, then reopen it to pick the default model.)
    • Use as the default endpoint — tick this to make new conversations use it automatically.
  • Edit: click the pencil icon on any endpoint. When editing, leave the key field blank to keep the existing key, or type a new value to replace it.
  • Delete: click the trash icon. Any conversation that used it falls back to the default endpoint.

In the endpoint list, each endpoint shows its default model. An endpoint that has no default model yet is flagged with a No default model badge so it's easy to spot.

The default endpoint must have a default model. You cannot save an endpoint marked as default without choosing a default model for it. Likewise, if you change which endpoint is the default and the new one has no default model identified, the app will require you to pick one first.

Only one endpoint can be the default at a time. Marking a new one as default automatically clears the flag on the others. Endpoints are stored in the app's local database, and their keys are never sent back to the browser — the list only shows whether a key is set.

Choosing an endpoint per conversation

The chat header has an Endpoint dropdown. Leave it on — Default — to use whichever endpoint is currently the default, or pick a specific endpoint to pin this conversation to it. Changing the endpoint reloads the model list for that provider and switches the conversation to that endpoint's default model, so the Model dropdown always reflects a sensible choice for the selected endpoint. This choice is saved with the conversation.

Example URLs: OpenAI https://api.openai.com/v1, Gemini https://generativelanguage.googleapis.com/v1beta/openai, LMStudio http://localhost:1234/v1, Ollama http://localhost:11434/v1.

4. Working with Conversations

  • Start a new conversation: click New Chat in the sidebar. It uses your default model (and the persona currently selected, if any).
  • Switch conversations: click any conversation in the sidebar to open it.
  • Automatic titles: a conversation is automatically named from your first message. You can rename it at any time with the pencil icon in the chat header.
  • Search: type in the sidebar search box to find conversations that contain a word or phrase; a short snippet of the match is shown.
  • Export: the download icon in the chat header saves the conversation as a tidy Markdown document (to your output folder, or as a browser download if no folder is set).
  • Delete: the trash icon removes a conversation permanently.

5. Sending Messages

  • Type in the box at the bottom and press Enter to send.
  • Use Shift + Enter to add a new line without sending.
  • Replies appear as they are generated. To interrupt a long reply, click the red Stop button that appears while the assistant is responding.
  • Edit a message: hover over one of your own messages and click the pencil icon. Editing re-sends from that point and replaces everything that came after.
  • Regenerate: hover over an assistant reply and click Regenerate to get a fresh answer to the same question.
  • Copy code: hover over any code block in a reply to reveal a copy button.

6. Personas

A persona tells the assistant to adopt a particular role or style — for example a Business Analyst, Python Developer, or Technical Writer. The application comes with several ready-made personas, and you can create your own.

  • Apply a persona: use the Persona dropdown in the chat header. The choice applies to that conversation.
  • Create or edit: open Settings, then use the New Persona button (or the pencil icon beside an existing one). Give it a name and describe how the assistant should behave.
  • A persona's instructions are added on top of the assistant's normal behaviour for the selected conversation.

7. Choosing a Model

The Model dropdown in the top bar controls which AI model answers the current conversation. Changing it affects only that conversation. New conversations start with the selected endpoint's default model (falling back to the app-wide fallback model in Settings if the endpoint has none). The available models come from the conversation's selected Endpoint, and switching endpoints adopts that endpoint's default model automatically.

Different models have different strengths, speeds, and context limits. If you are unsure, start with your default and switch only if you need a specific capability.

8. Attaching Files & Folders

You can give the assistant documents to read and reference. The toolbar beneath the message box offers four ways to do this:

ButtonWhat it does
Attach files (paperclip) Upload one or more individual files. Their text is extracted and made available to the assistant for the conversation.
Upload folder (folder with plus) Upload a whole folder. Supported files are copied to the application and their contents become available.
Link folder or file (folder with link) Point to a folder or an individual file on your computer. The content is read live from disk each time you chat — nothing is copied, and updates on disk are picked up automatically. Open the browser, then click a file to link it, or use the button to link the folder you are currently viewing. To link several items at once, tick their checkboxes and choose Link selected.
Import Markdown (markdown icon) Bring in a Markdown or text file specifically as background context.
  • Attached items appear as small chips above the message box. Click a chip's name to preview its extracted text, or the × to remove it.
  • Supported types include text and Markdown, common code files, PDFs, Word documents, Excel spreadsheets, CSVs, JSON/YAML, and more. Unsupported files are skipped automatically.
  • Large files: if a file (or linked folder) contains a very large amount of text, you will be warned, because it can slow responses or reduce answer quality. Very large files may be shortened so only the first portion is used.
  • The context badge in the chat header shows the estimated percentage of the configured context window in use, colour-coded from grey (comfortable) to red (very large). Set the model's context limit under Settings.

Uploaded vs. linked: Uploaded files are stored with the conversation. Linked folders stay where they are and are read fresh each time — ideal for a working project folder you keep changing.

9. Saving the AI's Work to Disk

When you ask the assistant to create or save a file, it writes it to your output folder. There are two levels of control:

  • Default Output Folder (in Settings) — applies everywhere unless overridden.
  • Per-conversation output folder — click the folder icon in the toolbar to set a different destination for just the current conversation. You can type a path or use the built-in Browse button to pick a folder. A per-conversation setting always takes priority over the default.

Save as files: when a reply is organised into several sections (each with its own heading), a Save as files button appears at the bottom of that reply. It splits the reply into separate files — one per section — and saves them all to your output folder. You can adjust each filename before saving.

10. What the Assistant Can Do (Tools)

Beyond answering in the chat, the assistant can perform a few practical actions when it genuinely helps with your request:

CapabilityDescription
Write a file Save content to your output folder — used when you ask for something to be created or saved.
Read a file Open and review a file already on disk so it can be analysed or updated.
List a folder See what files exist in a folder before reading or writing.
Run a calculation Execute a short piece of code to produce a concrete result — useful for data analysis, maths, or quick transformations.

When the assistant uses one of these, you will see a small notification in the chat confirming what happened (for example, that a file was saved and where).

The "Use Tools" toggle

Each conversation has a Use Tools toggle in the chat header (the wrench button, labelled Use Tools). It controls whether the abilities above are offered to the model for that conversation:

  • On (highlighted button) — the assistant may read/write files, list folders, and run calculations when it helps. This is the default for new conversations.
  • Off (plain button) — the assistant answers in the chat only and is not offered any tools.

The setting is remembered per conversation, so you can keep tools on in one chat and off in another. Click the button to switch; the change takes effect on your next message.

When to turn tools off: some AI services or locally-run models don't support the "function calling" feature these tools rely on and may return an error if it is requested. If a conversation fails as soon as you send a message, try turning Use Tools off for that conversation.

11. Settings Explained

All application-wide settings live in the Settings window (the gear icon). Here is what each one does and how it is applied:

SettingPurposeHow it is applied
API Endpoints The AI providers you can connect to (name, URL, key, default model). Managed at the top of Settings. The one marked default is used by new conversations; each conversation can override it from the header. A default endpoint must have a default model chosen.
Endpoint Default Model The model each endpoint uses by default. Set inside each endpoint's window. Applied to new conversations that use that endpoint, and adopted automatically when you switch a conversation to that endpoint.
Fallback Default Model A safety-net model used only when the active endpoint has no default model. Applied when you click New Chat and the endpoint has no default model of its own. Existing conversations keep their own model.
Folder Browser Starting Path Where the folder browser opens. Used whenever you browse for a folder. Optional.
Default Output Folder Where AI-written files are saved. Used for all conversations unless a conversation sets its own output folder.
Personas Reusable role/style profiles. Created and edited here; applied per conversation via the header dropdown.

Purge all conversations. At the bottom of Settings is a Purge option that permanently deletes every conversation, message, and uploaded file. Your settings and personas are kept. This cannot be undone — use it only when you are certain.

Reset Database. Below the Purge section is a Reset Database checkbox. Tick it and click Save to clear the core configuration values: the Fallback Default Model, each endpoint's own default model, the Folder Browser Starting Path, and the Default Output Folder. Your conversations and personas are kept. This cannot be undone. After a reset, the app will prompt you to re-enter these values the next time it starts if they are still empty.

How settings priority works

  • Endpoint: a per-conversation endpoint wins; otherwise the default endpoint is used.
  • Model: the model chosen in the top bar for the current conversation wins; otherwise the selected endpoint's default model is used; if the endpoint has none, the app-wide Fallback Default Model is used.
  • Output folder: a per-conversation folder wins; otherwise the Default Output Folder is used.
  • Reference material: if a conversation has both linked folders and uploaded files, linked folders take priority, and any uploaded file with the same name is not duplicated.
  • Tools: the Use Tools toggle is set per conversation and defaults to on for new conversations.

12. Tips & Troubleshooting

SituationWhat to check
The model list is empty or won't load Confirm the selected Endpoint's URL and key are correct in Settings, then reopen the conversation (or reselect the endpoint) to refresh the list.
Files aren't being saved Make sure a Default Output Folder (or a per-conversation folder) is set, and that the path exists and is spelled correctly.
Replies are slow or lower quality Check the token badge. Very large attachments or linked folders can overload the context — remove what you don't need.
An attached file was skipped Its type may not be supported. Convert it to a supported format such as PDF, Word, text, or Markdown.
Prefer a light background Use the sun/moon toggle in the top bar to switch between light and dark themes. Your choice is remembered.
Want to reuse a document across chats Link the folder rather than uploading — linked folders are read fresh each time and reflect any changes on disk.
A conversation errors as soon as you send a message The model may not support tool/function calling. Turn the Use Tools toggle in the chat header off for that conversation and try again.

A good starting workflow: set up your API details and output folder, choose a persona that fits the task, attach or link any reference material, then ask your question. Use Save as files or Export to keep the results.
